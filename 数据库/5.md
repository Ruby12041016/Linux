# MySQL 学习笔记五

# 一、为什么需要锁

数据库是一个多用户系统。

实际运行时：

```text
用户A
用户B
用户C
...
```

可能同时访问同一份数据。

如果没有控制机制：

```text
同时读取
同时修改
同时删除
```

就可能导致数据错误。

因此数据库需要：

```text
Lock（锁）
```

保证并发情况下的数据正确性。

---

# 二、锁解决什么问题

## 丢失更新（Lost Update）

账户余额：

| id | balance |
| -- | ------- |
| 1  | 1000    |

---

事务A：

```sql
SELECT balance
FROM account
WHERE id = 1;
```

读取：

```text
1000
```

准备扣：

```text
100
```

---

事务B：

```sql
SELECT balance
FROM account
WHERE id = 1;
```

也读取：

```text
1000
```

准备扣：

```text
200
```

---

事务A：

```sql
UPDATE account
SET balance = 900
WHERE id = 1;
```

---

事务B：

```sql
UPDATE account
SET balance = 800
WHERE id = 1;
```

---

最终结果：

```text
800
```

---

正确结果应该：

```text
1000 -100 -200

= 700
```

---

事务A的修改被覆盖。

发生：

```text
Lost Update
```

---

锁的目的：

```text
保证数据修改的正确性
```

---

# 三、什么是锁

锁（Lock）：

> 数据库用于协调多个事务并发访问数据的一种机制。

简单理解：

```text
先获得访问权限

再操作数据
```

---

现实例子：

```text
厕所门锁

会议室门锁

保险柜钥匙
```

本质相同。

---

数据库锁也是如此。

---

# 四、锁的作用

主要用于解决：

```text
并发访问问题
```

避免：

```text
脏写
丢失更新
数据覆盖
数据不一致
```

---

# 五、锁的分类

MySQL锁有很多种。

最常见分类：

```text
锁
│
├── 表锁
│
├── 行锁
│
├── 共享锁（S锁）
│
├── 排他锁（X锁）
│
├── Record Lock
│
├── Gap Lock
│
└── Next-Key Lock
```

---

# 六、表锁（Table Lock）

## 概念

锁住整张表。

---

例如：

```sql
LOCK TABLE student WRITE;
```

---

此时：

```text
student
```

整张表被锁。

---

其他事务：

```sql
SELECT
UPDATE
DELETE
INSERT
```

都会受到影响。

---

## 示例

表：

| id | name |
| -- | ---- |
| 1  | 张三   |
| 2  | 李四   |

---

事务A获得表锁。

---

事务B：

```sql
UPDATE student
SET name='王五'
WHERE id=1;
```

无法执行。

---

必须等待。

---

# 七、表锁特点

## 优点

实现简单。

开销小。

加锁速度快。

---

## 缺点

并发能力差。

---

例如：

```text
只修改1行

却锁住整个表
```

---

# 八、行锁（Row Lock）

## 概念

锁住指定记录。

---

例如：

```sql
SELECT *
FROM student
WHERE id=1
FOR UPDATE;
```

---

锁住：

```text
id=1
```

这一行。

---

其他行：

```text
id=2
id=3
id=4
```

仍然可以操作。

---

# 九、行锁特点

## 优点

并发能力强。

---

例如：

事务A：

```text
修改id=1
```

事务B：

```text
修改id=2
```

同时执行。

---

## 缺点

实现复杂。

维护成本高。

---

# 十、InnoDB为什么支持行锁

核心原因：

```text
索引
```

---

实际上：

```text
行锁 ≠ 锁数据行

行锁 = 锁索引记录
```

---

例如：

```sql
SELECT *
FROM student
WHERE id=1
FOR UPDATE;
```

---

主键：

```text
id
```

存在索引。

---

数据库通过索引直接定位：

```text
id=1
```

并加锁。

---

# 十一、没有索引会怎样

例如：

```sql
SELECT *
FROM student
WHERE name='张三'
FOR UPDATE;
```

---

name字段没有索引。

---

数据库必须：

```text
全表扫描
```

---

最终可能导致：

```text
行锁退化为表锁
```

---

# 十二、共享锁（Shared Lock）

简称：

```text
S Lock
```

---

## 特点

允许多个事务同时读取。

不允许修改。

---

理解：

```text
多人同时看一本书
```

可以。

---

但：

```text
不能修改书内容
```

---

## 获取方式

MySQL 8：

```sql
SELECT *
FROM student
WHERE id=1
FOR SHARE;
```

---

MySQL 5.x：

```sql
SELECT *
FROM student
WHERE id=1
LOCK IN SHARE MODE;
```

---

# 十三、排他锁（Exclusive Lock）

简称：

```text
X Lock
```

---

## 特点

独占访问。

---

获取后：

```text
其他事务不能修改
```

---

通常：

```sql
SELECT *
FROM student
WHERE id=1
FOR UPDATE;
```

获得。

---

# 十四、S锁与X锁兼容性

| 当前锁 | 新S锁 | 新X锁 |
| --- | --- | --- |
| S锁  | 允许  | 不允许 |
| X锁  | 不允许 | 不允许 |

---

记忆口诀：

```text
读读共享

读写互斥

写写互斥
```

---

# 十五、快照读（Snapshot Read）

普通查询：

```sql
SELECT *
FROM student;
```

---

特点：

```text
不加锁
```

---

使用：

```text
MVCC
```

读取历史版本。

---

属于：

```text
快照读
```

---

# 十六、当前读（Current Read）

读取最新版本数据。

并加锁。

---

例如：

```sql
SELECT *
FROM student
FOR UPDATE;
```

---

或者：

```sql
UPDATE ...
```

```sql
DELETE ...
```

---

属于：

```text
当前读
```

---

# 十七、Record Lock（记录锁）

## 概念

锁定某条索引记录。

---

例如：

```sql
SELECT *
FROM student
WHERE id=10
FOR UPDATE;
```

---

锁住：

```text
id=10
```

对应记录。

---

# 十八、Gap Lock（间隙锁）

## 概念

锁定索引之间的空隙。

---

数据：

| id |
| -- |
| 10 |
| 20 |
| 30 |

---

事务A：

```sql
SELECT *
FROM student
WHERE id BETWEEN 10 AND 20
FOR UPDATE;
```

---

不仅锁：

```text
10
20
```

---

还锁：

```text
(10,20)
```

之间的空隙。

---

# 十九、Gap Lock作用

防止：

```text
幻读
```

---

否则：

事务A第一次查询：

```text
10
20
```

---

事务B：

```sql
INSERT INTO student
VALUES(15);
```

---

事务A再次查询：

```text
10
15
20
```

---

结果变化。

发生：

```text
幻读
```

---

Gap Lock禁止这种插入。

---

# 二十、Next-Key Lock

## 概念

InnoDB默认使用。

---

公式：

```text
Next-Key Lock

=

Record Lock

+

Gap Lock
```

---

例如：

```sql
SELECT *
FROM student
WHERE id=20
FOR UPDATE;
```

---

锁住：

```text
记录20

+

前面的间隙
```

---

既不能修改。

也不能插入。

---

# 二十一、意向锁（Intention Lock）

## 为什么需要意向锁

假设：

事务A：

```text
锁住10000行
```

---

事务B：

想加表锁。

---

如果没有额外机制：

数据库必须检查：

```text
10000行
```

是否被锁。

---

效率极低。

---

因此引入：

```text
意向锁
```

---

## 本质

告诉数据库：

```text
我准备锁某些行
```

---

## 分类

### IS

Intention Shared Lock

意向共享锁

---

### IX

Intention Exclusive Lock

意向排他锁

---

用户通常不会手动使用。

由InnoDB自动维护。

---

# 二十二、死锁（Dead Lock）

## 概念

两个事务互相等待。

永远无法继续。

---

事务A：

锁住：

```text
id=1
```

---

事务B：

锁住：

```text
id=2
```

---

然后：

事务A：

```text
请求id=2
```

等待。

---

事务B：

```text
请求id=1
```

等待。

---

形成：

```text
A等B

B等A
```

---

这就是：

```text
Dead Lock
```

---

# 二十三、死锁检测

InnoDB内部：

```text
Deadlock Detector
```

死锁检测器。

---

发现死锁后：

```text
自动终止一个事务
```

---

返回：

```text
Deadlock found
```

错误信息。

---

# 二十四、避免死锁的方法

## 统一加锁顺序

例如：

```text
先锁用户表

再锁订单表
```

所有事务保持一致。

---

## 缩短事务时间

不要：

```text
开启事务后长时间不提交
```

---

## 及时提交

```sql
COMMIT;
```

---

## 使用合理索引

避免：

```text
锁范围过大
```

---
