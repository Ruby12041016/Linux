# MySQL 学习笔记四

# 一、事务产生的背景

数据库最重要的任务不是存储数据，而是保证数据的正确性。

在实际业务中，一个功能往往需要执行多条 SQL。

例如银行转账：

```sql
UPDATE account
SET balance = balance - 100
WHERE id = 1;

UPDATE account
SET balance = balance + 100
WHERE id = 2;
```

如果第一条 SQL 执行成功后，服务器突然崩溃：

```text
张三：1000 → 900

李四：500 → 500
```

此时：

```text
总金额：

1000 + 500 = 1500

900 + 500 = 1400
```

数据发生错误。

因此数据库需要一种机制保证：

```text
要么全部成功

要么全部失败
```

这就是事务。

---

# 二、什么是事务

事务（Transaction）：

> 一组逻辑操作单元，这组操作要么全部成功，要么全部失败。

简单理解：

```text
把多条 SQL 打包成一个整体
```

例如：

```text
扣钱

加钱

生成流水

发送通知
```

这些操作必须同时成功。

否则全部取消。

---


# 三、ACID 四大特性

事务必须满足 ACID。

| 缩写 | 全称          | 中文  |
| -- | ----------- | --- |
| A  | Atomicity   | 原子性 |
| C  | Consistency | 一致性 |
| I  | Isolation   | 隔离性 |
| D  | Durability  | 持久性 |

---

# 四、Atomicity（原子性）

## 定义

事务中的所有操作：

```text
要么全部成功

要么全部失败
```

不能执行一半。

---

## 示例

转账：

```sql
UPDATE account
SET balance = balance - 100
WHERE id = 1;

UPDATE account
SET balance = balance + 100
WHERE id = 2;
```

如果第二条失败：

```text
第一条也必须撤销
```

恢复原始状态。

---

## 实现机制

```text
Undo Log
```

回滚日志。

记录修改前的数据。

发生回滚时恢复。

---

# 五、Consistency（一致性）

## 定义

事务执行前后：

```text
数据库始终满足业务规则
```

---

## 示例

转账前：

```text
张三：1000

李四：500
```

总金额：

```text
1500
```

---

转账后：

```text
张三：900

李四：600
```

总金额：

```text
1500
```

保持一致。

---

## 一致性的体现

### 主键唯一

```sql
PRIMARY KEY
```

---

### 非空约束

```sql
NOT NULL
```

---

### 唯一约束

```sql
UNIQUE
```

---

### 外键约束

```sql
FOREIGN KEY
```

---

# 六、Isolation（隔离性）

## 定义

多个事务同时执行时：

```text
互不干扰
```

---

## 目的

避免：

```text
脏读

不可重复读

幻读
```

---

## 实现机制

```text
MVCC

Lock
```

---

# 七、Durability（持久性）

## 定义

事务提交后：

```text
永久保存
```

即使：

```text
断电

数据库崩溃

服务器重启
```

也不能丢失。

---

## 实现机制

```text
Redo Log
```

---

# 八、ACID 实现机制总结

| ACID        | 实现方式        |
| ----------- | ----------- |
| Atomicity   | Undo Log    |
| Consistency | 多机制共同保证     |
| Isolation   | MVCC + Lock |
| Durability  | Redo Log    |

---

# 九、事务控制语句

## 开启事务

```sql
START TRANSACTION;
```

或者：

```sql
BEGIN;
```

---

## 提交事务

```sql
COMMIT;
```

作用：

```text
正式保存修改
```

---

## 回滚事务

```sql
ROLLBACK;
```

作用：

```text
撤销修改
```

恢复事务开始前状态。

---

# 十、AUTOCOMMIT

查看：

```sql
SELECT @@autocommit;
```

---

结果：

```text
1
```

表示：

```text
自动提交开启
```

---

关闭：

```sql
SET autocommit = 0;
```

---

开启：

```sql
SET autocommit = 1;
```

---

# 十一、事务执行流程

```text
START TRANSACTION
          ↓
执行 SQL
          ↓
记录 Undo Log
          ↓
记录 Redo Log
          ↓
COMMIT
          ↓
释放锁
```

---

# 十二、SAVEPOINT（保存点）

## 创建保存点

```sql
SAVEPOINT p1;
```

---

## 回滚到保存点

```sql
ROLLBACK TO p1;
```

---

## 删除保存点

```sql
RELEASE SAVEPOINT p1;
```

---

# 十三、并发事务问题

数据库多个事务同时执行时会出现问题。

---

# 十四、脏读（Dirty Read）

## 定义

读取到：

```text
其他事务未提交的数据
```

---

## 示例

事务A：

```sql
UPDATE account
SET balance = 2000
WHERE id = 1;
```

未提交。

---

事务B：

```sql
SELECT balance
FROM account
WHERE id = 1;
```

读取到：

```text
2000
```

---

事务A：

```sql
ROLLBACK;
```

---

余额恢复：

```text
1000
```

---

事务B读取的数据不存在。

发生脏读。

---

# 十五、不可重复读（Non Repeatable Read）

## 定义

同一个事务中：

```text
两次读取同一条记录

结果不同
```

---

## 示例

第一次：

```text
1000
```

---

其他事务：

```text
修改为2000
提交
```

---

第二次：

```text
2000
```

---

发生不可重复读。

---

# 十六、幻读（Phantom Read）

## 定义

同一个事务中：

```text
两次范围查询

记录数量发生变化
```

---

## 示例

第一次：

```sql
SELECT *
FROM orders
WHERE amount > 100;
```

结果：

```text
1条记录
```

---

其他事务：

```sql
INSERT ...
```

提交。

---

再次查询：

```text
2条记录
```

---

多出来的记录称为：

```text
幻影记录
```

---

# 十七、四种隔离级别

| 隔离级别             | 脏读 | 不可重复读 | 幻读  |
| ---------------- | -- | ----- | --- |
| Read Uncommitted | 有  | 有     | 有   |
| Read Committed   | 无  | 有     | 有   |
| Repeatable Read  | 无  | 无     | 理论有 |
| Serializable     | 无  | 无     | 无   |

---

# 十八、Read Uncommitted（RU）

## 特点

```text
允许读取未提交数据
```

---

## 优点

```text
最快
```

---

## 缺点

```text
最不安全
```

---

# 十九、Read Committed（RC）

## 特点

```text
只能读取已提交数据
```

---

## 解决

```text
脏读
```

---

## 无法解决

```text
不可重复读

幻读
```

---

# 二十、Repeatable Read（RR）

## 特点

事务开始时看到什么：

```text
后面一直看到什么
```

---

## 解决

```text
脏读

不可重复读
```

---

## MySQL默认隔离级别

```text
REPEATABLE READ
```

---

## 实现机制

```text
MVCC
```

---

# 二十一、Serializable

## 特点

事务串行执行。

```text
一个事务执行时

其他事务等待
```

---

## 优点

```text
最安全
```

---

## 缺点

```text
性能最差
```

---

# 二十二、查看隔离级别

```sql
SELECT @@transaction_isolation;
```

---

# 二十三、修改隔离级别

当前会话：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

---

全局：

```sql
SET GLOBAL TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

---

# 二十四、MVCC（多版本并发控制）

全称：

```text
Multi-Version Concurrency Control
```

---

## 核心思想

```text
保留历史版本数据
```

---

## 目的

解决：

```text
读写冲突
```

---

## 效果

```text
查询不阻塞更新

更新不阻塞查询
```

---

# 二十五、MVCC依赖机制

```text
隐藏字段

Undo Log

版本链

Read View
```

---

# 二十六、隐藏字段

InnoDB内部自动维护：

```text
trx_id

roll_pointer
```

---

# 二十七、trx_id

事务ID。

记录：

```text
最后修改该行数据的事务
```

---

# 二十八、roll_pointer

回滚指针。

作用：

```text
指向旧版本
```

---

# 二十九、Undo Log

作用一：

```text
事务回滚
```

---

作用二：

```text
MVCC读取历史版本
```

---

# 三十、版本链（Version Chain）

例如：

```text
2000
 ↓

1500
 ↓

1200
 ↓

1000
```

---

每次更新：

```text
生成新版本
```

---

# 三十一、Read View

作用：

```text
决定当前事务可以看到哪些版本
```

---

事务开始时创建。

后续查询根据 Read View 判断可见性。

---

# 三十二、快照读（Snapshot Read）

普通查询：

```sql
SELECT *
FROM user;
```

---

特点：

```text
读取历史版本

不加锁
```

---

依赖：

```text
MVCC
```

---

# 三十三、当前读（Current Read）

读取最新数据。

例如：

```sql
SELECT *
FROM user
FOR UPDATE;
```

```sql
UPDATE ...
```

```sql
DELETE ...
```

---

特点：

```text
读取最新版本

加锁
```

---
