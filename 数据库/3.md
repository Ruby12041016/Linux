# MySQL 学习笔记三

# 一、为什么需要索引

## 1. 问题背景

假设有一张学生表：

```sql
CREATE TABLE student(
    id INT PRIMARY KEY,
    name VARCHAR(20),
    age INT
);
```

随着数据不断增加，查询速度会越来越慢。

如果没有索引，MySQL需要从第一行开始逐个比较，直到找到目标数据。

这种查询方式称为：

```text
Full Table Scan
全表扫描
```
---

## 2. 全表扫描的特点

优点：

```text
实现简单
不需要额外存储空间
```

---

缺点：

```text
数据量越大越慢
效率极低
```

---

# 二、什么是索引

## 1. 定义

索引（Index）：

```text
帮助数据库快速定位数据的一种数据结构
```

---

本质：

```text
空间换时间
```

---

是数据库额外维护一份特殊的数据结构，查询时先查索引，再通过索引定位数据。

---

# 三、主键索引

## 1. 主键自动创建索引

创建表：

```sql
CREATE TABLE student(
    id INT PRIMARY KEY,
    name VARCHAR(20)
);
```

---

执行：

```sql
PRIMARY KEY
```

时：

MySQL自动创建：

```text
主键索引
Primary Index
```

---

## 2. 主键索引特点

特点：

```text
唯一
非空
自动建立索引
```

---

因此：

```sql
SELECT *
FROM student
WHERE id = 1;
```

通常非常快。

---

# 四、索引的数据结构

MySQL InnoDB：

```text
默认使用 B+Tree
```

---


# 五、为什么不用数组

数组：

```text
1
2
3
4
5
6
...
```

---

查找：

```text
二分查找
```

速度快，但是在中间插入数据需要移动大量元素。

---

# 六、为什么不用链表

链表：

```text
1 → 2 → 3 → 4 → 5
```

---

查找：

```text
5
```

必须依次遍历。

---

时间复杂度：

```text
O(n)
```

---

效率太低。

---

# 七、B树（了解）

结构：

```text
          50
       /      \
     20        80
   /   \      /   \
 10   30    70   90
```

---

特点：

```text
多路平衡搜索树
```

---

优点：

```text
树高度低
磁盘访问次数少
```

---

# 八、B+树（重点）

MySQL InnoDB真正使用：

```text
B+Tree
```

---

## 1. 结构特点

### 非叶子节点

只保存：

```text
索引键(Key)
```

---

不保存完整数据。

---

### 叶子节点

保存：

```text
完整数据
```

或者：

```text
数据地址
```

---

## 2. 叶子节点链表

B+树叶子节点之间：

```text
按顺序连接
```

例如：

```text
1 → 2 → 3 → 4 → 5
```

---

因此：

```sql
BETWEEN
ORDER BY
范围查询
```

效率很高。

---

## 3. 树高很低

即使：

```text
1000万条数据
```

树高可能只有：

```text
3~4层
```

---

查询：

```sql
WHERE id=1000000
```

只需要：

```text
3~4次磁盘IO
```

即可找到。

---

# 九、查看索引

查看表中索引：

```sql
SHOW INDEX
FROM student;
```

---

重点字段：

| 字段 | 含义 |
|--------|--------|
| Key_name | 索引名称 |
| Column_name | 字段名 |
| Non_unique | 是否允许重复 |
| Index_type | 索引类型 |

---

# 十、创建普通索引

## 语法

```sql
CREATE INDEX 索引名
ON 表名(字段名);
```

---

示例：

```sql
CREATE INDEX idx_name
ON student(name);
```

---

解释：

```text
idx_name
```

索引名称。

---

```text
student(name)
```

给name字段建立索引。

---

# 十一、删除索引

## 语法

```sql
DROP INDEX 索引名
ON 表名;
```

---

示例：

```sql
DROP INDEX idx_name
ON student;
```

---

# 十二、唯一索引

创建：

```sql
CREATE UNIQUE INDEX idx_phone
ON student(phone);
```

---

特点：

```text
建立索引
同时保证唯一性
```

---

效果类似：

```sql
phone VARCHAR(11) UNIQUE
```

---

# 十三、二级索引（Secondary Index）

除主键索引外：

所有普通索引都属于：

```text
Secondary Index
二级索引
```

---

例如：

```sql
CREATE INDEX idx_name
ON student(name);
```

---

就是二级索引。

---

# 十四、联合索引（Composite Index）

## 创建

```sql
CREATE INDEX idx_name_age
ON student(name, age);
```

---

索引顺序：

```text
name
↓
age
```

---

## 使用场景

经常查询：

```sql
WHERE name='张三'
AND age=18
```

---

使用联合索引效率更高。

---

# 十五、最左前缀原则

假设：

```sql
CREATE INDEX idx_abc
ON student(name, age, class_id);
```

---

索引顺序：

```text
name
↓
age
↓
class_id
```

---

## 能使用索引

```sql
WHERE name='张三'
```

---

```sql
WHERE name='张三'
AND age=18
```

---

```sql
WHERE name='张三'
AND age=18
AND class_id=1
```

---

## 不能充分使用索引

```sql
WHERE age=18
```

---

```sql
WHERE class_id=1
```

---

```sql
WHERE age=18
AND class_id=1
```

---

原因：

```text
必须从最左边开始匹配
```

---

记忆口诀：

```text
联合索引从左向右
不能跳列
```

---

# 十六、EXPLAIN 执行计划

## 作用

查看：

```text
MySQL如何执行SQL
```

---

语法：

```sql
EXPLAIN
SELECT *
FROM student
WHERE name='张三';
```

---

# 十七、EXPLAIN重要字段

## type

最重要字段。

---

优秀：

```text
const
eq_ref
ref
range
```

---

一般：

```text
index
```

---

最差：

```text
ALL
```

---

ALL表示：

```text
全表扫描
```

---

## key

实际使用的索引。

例如：

```text
idx_name
```

---

如果：

```text
NULL
```

说明没用索引。

---

## rows

预计扫描行数。

例如：

```text
100000
```

表示：

```text
预计扫描10万行
```

---

通常越小越好。

---

# 十八、适合建立索引的字段

## 主键

```sql
id
```

---

## 经常查询

```sql
username
```

---

## 经常排序

```sql
create_time
```

---

## 经常JOIN

```sql
user_id
```

---

## 经常作为条件

```sql
WHERE phone='xxx'
```

---

# 十九、不适合建立索引的字段

## 性别

```sql
gender
```

数据：

```text
男
女
```

---

区分度太低。

---

## 删除标记

```sql
is_deleted
```

数据：

```text
0
1
```

---

也不适合。

---

## 很少查询的字段

例如：

```sql
remark
description
```

---

建立索引意义不大。

---

# 二十、索引优缺点

## 优点

### 提高查询速度

```sql
WHERE
```

---

### 提高排序速度

```sql
ORDER BY
```

---

### 提高JOIN效率

```sql
JOIN
```

---

### 提高分组效率

```sql
GROUP BY
```

---

## 缺点

### 占用磁盘空间

索引需要额外存储。

---

### 降低插入速度

```sql
INSERT
```

时：

数据写入。

索引也要更新。

---

### 降低修改速度

```sql
UPDATE
```

时：

索引也需要调整。

---

### 降低删除速度

```sql
DELETE
```

时：

索引也需要维护。

---
