# Redis 学习笔记

1. Redis 和 MySQL 最大区别：MySQL 存硬盘，用来永久存数据，速度慢；Redis 存内存，速度极快，专门用来做缓存、提速、抗高并发。MySQL 有库、有表、有行有列，需要先建表再存数据；Redis **没有表、没有字段、不用建表**，全程是 key\-value 键值对结构，靠 key 的命名来模拟表和数据分类，比如 user:1、order:1001 就相当于虚拟的用户表、订单表。Redis 默认有 16 个数据库，用 SELECT 0\-15 切换，仅仅是用来隔离数据，库里依旧没有表结构。

2. Redis 不需要建表、建字段、设计结构，想存数据直接写命令即可，这是它和关系型数据库最大的区别。所有以相同前缀开头的 key，业务上就视为一张虚拟表，比如所有 user: 开头的 key 就是用户表，所有 goods: 开头的 key 就是商品表。

3. Redis 一共五种核心数据结构，是日常开发百分百会用到的。String 字符串是最基础的结构，可以存文字、数字、字符串，适合存验证码、token、计数器、简单缓存，常用命令有 SET 存数据、GET 取数据、INCR 数字自增、MSET 批量存、MGET 批量取，设置缓存必须加过期时间，命令为 SET key value EX 秒数，避免内存溢出。

4. Hash 哈希结构相当于 Redis 的“对象表”，专门用来存一整条数据，比如用户信息、商品信息，替代多条 String 存储，结构更清晰。常用命令 HSET 设置对象字段、HGET 取单个字段、HGETALL 取出整条对象数据，开发中存用户基本信息、商品参数首选 Hash。

5. List 列表是有序可重复的队列结构，底层是双向链表，两头操作速度极快，适合做简单消息队列、排队数据、日志列表。常用命令 RPUSH 右侧入队、LPOP/RPOP 弹出数据、LRANGE 查看列表所有内容，遵循先进先出的队列规则。

6. Set 集合无序、自动去重，不允许重复数据，适合做签到统计、访客去重、好友列表、抽奖功能。常用命令 SADD 添加元素、SMEMBERS 查看所有元素、SISMEMBER 判断元素是否存在、SPOP 随机弹出元素实现抽奖，还支持交集、并集、差集，用来计算共同好友等场景。

7. ZSet 有序集合，不重复且自带分数排序，是 Redis 的排行榜专用结构，通过 score 分数实现自动排序。常用命令 ZADD 添加带分数的数据、ZREVRANGE 倒序查询实现排行榜、ZINCRBY 修改分数，适用于热度排行、积分排名、延迟队列等场景。

8. Redis 通用基础命令是开发必掌握的核心，EXISTS 判断 key 是否存在、DEL 删除数据、EXPIRE 设置过期时间、TTL 查看剩余过期时间、PERSIST 取消过期。线上绝对禁止使用 KEYS \* 命令，该命令会遍历所有 key，阻塞整个 Redis，导致服务卡顿，生产环境批量查询数据只能用 SCAN。FLUSHDB 清空当前库数据、FLUSHALL 清空所有库数据，仅可本地测试使用，线上严禁执行。

9. Redis 连接池是项目开发的重中之重，原生 Redis 基于 TCP 连接，每次新建连接、关闭连接非常消耗资源，高并发场景下会出现端口耗尽、服务卡顿的问题。连接池会在程序启动时提前创建一批可用连接，统一存放在池中，业务使用时直接取用，使用完毕归还池子，不关闭连接，实现连接复用。核心参数有最大连接数（限制并发上限）、最小空闲连接（常驻待命，避免重复创建）、最大等待时间（拿不到连接直接报错，防止线程卡死），所有正规项目必须配置连接池，禁止裸连接直连 Redis。

10. Redis 内存断电会丢失，所以提供两种持久化方案保证数据不丢。RDB 是快照持久化，定时把内存所有数据保存到硬盘文件，优点是体积小、恢复快，缺点是两次快照之间断电会丢失增量数据。AOF 是日志持久化，记录每一条写命令，优点是几乎不丢数据，缺点是文件体积大。生产环境一般开启混合持久化，兼顾两者优势。

11. Redis 内存满了会自动触发淘汰策略，最常用的是 allkeys\-lru，淘汰最近最少使用的 key，是业务通用最优策略，保证热点数据常驻内存，冷门数据自动清理。所有缓存数据必须设置过期时间，避免大量数据永久占用内存，导致 Redis 内存溢出。

12. Redis 高可用三种架构，单机适合测试环境；主从复制是一主多从，主节点写、从节点读，实现读写分离和数据备份，缺点是主节点宕机需要手动切换；哨兵模式自动监控主从节点，主节点宕机自动故障转移，适合中小型项目；Cluster 集群模式分片存储，16384 个哈希槽分配数据，支持海量数据和高并发，可横向扩容，适合大型项目。

13. Redis 核心业务场景全覆盖，日常开发用来做热点数据缓存，减轻 MySQL 压力；INCR 实现点赞、访问量、库存计数器；ZSet 实现各类排行榜；Set 实现数据去重；String 存储验证码、分布式 Session；Lua 脚本实现分布式锁、接口限流；List 和 Stream 实现简易消息队列。

14. Redis 开发避坑要点：禁止使用 KEYS \*、禁止存超大 key、禁止大量 key 同一时间过期导致缓存雪崩、必须配置连接池、必须设置内存淘汰策略、冷热数据分离，Redis 只存高频热点数据，海量冷门数据存 MySQL。

## 一、Redis 核心概念
### 1.1 什么是 Redis
Redis 是内存级高速 NoSQL 数据库，主要用来做缓存、提速。
- 数据默认存在内存 → 速度极快
- 支持 5 种常用数据结构
- 无表结构、无 SQL
- 可持久化到硬盘（防止断电丢失）

### 1.2 Redis 怎么“建表”？
Redis 没有建表语句！没有表！
我们通过 key 命名模拟表（工作统一规范）：
- user:1、user:2 -> 模拟用户表
- order:1001 -> 模拟订单表
- goods:200 -> 模拟商品表
冒号前面 = 表名，冒号后面 = id

## 二、Redis 基础操作
### 2.1 启动与连接
#### 启动服务端

```c
redis-server
```

##### 启动客户端

```c
redis-cli
```

### 2.2 通用命令（所有数据通用）

```text
SET k1 v1        # 存数据
GET k1           # 取数据
DEL k1           # 删除 key
EXISTS k1        # 判断是否存在 1存在 0不存在
EXPIRE k1 60     # 设置60秒过期
TTL k1           # 查看剩余过期时间
TYPE k1          # 查看数据类型
FLUSHDB          # 清空当前库（测试用）
SELECT 1         # 切换1号数据库（共0-15）
```

## 三、五大核心数据结构（最常用）
### 3.1 String 字符串（最简单、最多用）
存：文本、数字、验证码、token、计数器
```text
SET name 小明
GET name

SET code 123456 EX 60   # 60秒过期
INCR num                # 数字自增（点赞、访问量）
MSET a 1 b 2 c 3        # 批量存
MGET a b c              # 批量取
```
### 3.2 Hash 哈希（存对象、替代 MySQL 单表数据）
适合：用户信息、商品信息（一条数据多个字段）
#### 模拟 user 表
```text
HSET user:1 name 张三 age 18
HGET user:1 name
HGETALL user:1       # 查询整条用户数据
HINCRBY user:1 age 1 # 年龄+1
```
### 3.3 List 列表（队列、有序可重复）
特点：两头操作快，中间查慢
用途：消息队列、排队列表
```text
RPUSH list a b c   # 右边入队
LPUSH list x       # 左边入队
LRANGE list 0 -1   # 查询全部
RPOP list          # 右边弹出（队列）
LPOP list          # 左边弹出（栈）
```
### 3.4 Set 集合（无序、自动去重）
用途：签到、UV统计、好友去重
```text
SADD s1 1 2 2 3
SMEMBERS s1   # 查看所有（自动去重）
SISMEMBER s1 2 # 判断是否存在
SREM s1 2      # 删除元素
```
### 3.5 ZSet 有序集合（排行榜专用）
带分数、自动排序、不可重复
```text
ZADD rank 90 小明
ZADD rank 95 小红
ZADD rank 70 小刚

ZRANGE rank 0 -1 WITHSCORES    # 升序
ZREVRANGE rank 0 -1 WITHSCORES # 降序（排行榜）
```

## 四、Redis 连接池
### 4.1 什么是连接池（大白话）
每次操作 Redis 不用反复“创建网线、剪断网线”。
程序启动预先创建一堆连接，用完归还不关闭，大幅提速、防卡死。
### 4.2 核心参数
- maxTotal：最大连接数（最高并发）
- minIdle：最小空闲连接（常驻待命）
- maxWait：拿不到连接的超时时间
### 4.3 为什么必须用连接池
- 频繁新建连接：耗 CPU、占端口、服务卡死
- 连接池：复用连接，稳定、高性能

---
## 五、Redis 持久化（防止断电丢数据）
### 5.1 RDB（快照）
定时把整份内存数据保存到硬盘
- 优点：文件小、恢复快
- 缺点：会丢最近一小段数据
### 5.2 AOF（日志）
记录每一条写命令
- 优点：几乎不丢数据
- 缺点：文件大、恢复慢
生产推荐：RDB+AOF 混合持久化

---
## 六、Redis 内存淘汰策略（满了删谁）
内存占满自动删 key，最常用两种：
- allkeys-lru：删除最近最少使用（业务通用首选）
- volatile-ttl：优先删快要过期的

---
## 七、工作标准业务流程
用户请求 → 先查 Redis
有数据 → 直接返回（快）
无数据 → 查询 MySQL → 写入 Redis（加过期时间）→ 返回

## 八、Redis 常用场景
- 热点数据缓存（商品、首页）
- 验证码、Token、登录会话
- 计数器、点赞、浏览量
- 排行榜（ZSet）
- 分布式锁
- 简单消息队列
- UV 去重统计（Set）
